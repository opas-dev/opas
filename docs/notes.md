# Runtime constraints

## Cloudflare Workers and D1

The Next.js application builds with `@opennextjs/cloudflare` 1.20.4 and runs against the D1 dialect through the same repository contract used by Postgres. Fresh local Wrangler migrations and the deployment seed complete successfully, and changing the D1 article row changes the next rendered response without rebuilding.

Workerd rejects request-time dynamic evaluation. OPAS therefore compiles MDX to a function body inside the Worker and executes that body in the browser. Public content rendering consequently needs `unsafe-eval` in `script-src`; the content must pass the MDX allowlist added in item 3.3 before compiling or editing ships.

Fumadocs uses its minimal runtime preset, with the unused documentation-plugin import excluded. This removed the Shiki initialization path and reduced the spike Worker from 3.126 MiB to about 1.27 MiB compressed. The Phase 1 bundle is about 1.44 MiB compressed after adding all database adapters.

## Runtime themes

Runtime themes may change values only within OPAS's predefined semantic color, font, and radius tokens. Adding a token or a Tailwind utility requires a rebuild. Font stacks may reference only fonts already available to the browser; changing a stack does not load a font file.

The root server layout validates and injects the active database row on every request. The authenticated editor writes one trusted workspace row through the shared repository, and public reloads observe the change immediately. [`theme-before.png`](theme-before.png) and [`theme-after.png`](theme-after.png) show OPAS Default and Ocean from the same production build and server process; both light and dark computed values were verified, then the local row was restored.

Named-member session cookies are signed, deployment-scoped, limited to `/admin`, and expire no later than their database session. Each protected request verifies the minimal workspace and session claims, then reloads the active member, current role, and unrevoked session from the database before authorizing an exact capability. Disabling a member, changing a role, revoking the session, or rotating the signing secret therefore takes effect without waiting for the cookie to expire. Production cookies are always Secure, so production admin access requires HTTPS. OpenNext labels Node.js Proxy support experimental during its Cloudflare build; the workerd boundary redirects an unauthenticated request to `/admin/login`.

## MDX threat model

Article rows are untrusted at render time even when they normally come from the authenticated editor: an import, a compromised database credential, or a future write path must not turn content into application code. Fumadocs compiles MDX to a JavaScript function body and executes it with a dynamic function on Node or in the browser on Cloudflare, where the renderer also requires `unsafe-eval`.

Every article therefore passes through the MDX parser before either execution path. The validator rejects module imports and exports, frontmatter, inline and block JavaScript expressions, expression-valued or spread component properties, unsafe link and image protocols, and every JSX element outside the registered component allowlist. Inline links may use HTTP(S), mail, or telephone destinations; external images require HTTPS. Reference definitions use the narrower relative-or-HTTPS policy because Markdown shares definitions between links and images. The v0.1 component allowlist is empty because OPAS currently registers no custom article components; normal Markdown, including fenced and inline code examples that contain those strings, remains valid. A future component must be registered in the renderer and explicitly admitted here only after its properties and output are audited.

This boundary prevents stored content from intentionally reaching the MDX execution surface; it does not make `unsafe-eval` harmless or protect against a compiler/runtime vulnerability. The authenticated live preview also executes validated compiled MDX in the browser on every deployment target, while public browser execution is Cloudflare-specific. The static CSP applies `unsafe-eval` to every route because both public Cloudflare articles and authenticated previews share the same Next.js deployment; all permitted script origins remain same-origin.

## Knowledge migration and Visual authoring

OPAS imports one Markdown file or a bounded ZIP. ZIP input is capped at 4 MiB compressed, 24 MiB expanded, 2 MiB per file, 100 entries, and a 100:1 expansion ratio. The 4 MiB request cap stays below [Vercel Functions' 4.5 MB payload limit](https://vercel.com/docs/functions/limitations). The parser validates central and local ZIP metadata, checks CRC values, rejects encryption, links and special files, nested archives, unsafe or duplicate normalized paths, and performs no filesystem extraction.

GitBook `SUMMARY.md` supplies order when present. The first navigation level becomes OPAS categories; deeper page paths flatten into deterministic workspace-unique slugs. Frontmatter is parsed before storage, allowlisted fields have explicit precedence, secondary H1s are demoted, relative article and image targets are rewritten through the parsed Markdown tree, and the dry-run report exposes every conflict, repair, rename, unknown field, redirect candidate, and skipped file. Activation stages one asset manifest and performs one atomic repository operation; PostgreSQL uses a transaction, Neon and D1 use one batch, and local SQLite uses a transaction. Cloudflare documents that [`D1Database.batch()` is transactional and rolls back the sequence on failure](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch).

Images are limited to signed PNG, JPEG, GIF, or WebP data no larger than 1 MiB, keyed by SHA-256, and stored in matching binary rows. This leaves headroom below D1's [2 MB BLOB and row limit](https://developers.cloudflare.com/d1/platform/limits/). Imports are capped at 100 entries so their bounded activation stays below the paid D1 limit of 1,000 queries per Worker invocation. Staged and draft assets are readable only through the authenticated admin route; the immutable public hash route returns an asset only when a published article in the workspace references it. Save, cancellation, manifest expiry, detachment, article deletion, and failed activation all remove unreferenced rows.

Visual and Source modes edit one canonical Markdown value. The shared `remark-parse` plus GFM contract drives parsing, H1 ownership, validation, preview, Node and workerd compilation, import, and export. MDXEditor is client-only and therefore absent from server rendering; unsupported valid syntax stays in Source mode instead of being normalized. The title field owns the single first H1, Visual mode edits only the remaining body, and title-aware preview applies the same check as save. Tables, lists, links, code, allowed images, undo/redo, safe plain-text paste, keyboard tabs, and authenticated image previews remain inside the existing safe-MDX boundary.

A fresh production manifest inspection found no MDXEditor, Lexical, table-toolbar, or Visual-editor markers in either public article chunk. The isolated editor chunk is 701,673 bytes uncompressed and 221,359 bytes with gzip in this build, and is reachable only from authenticated authoring routes.

Browser-side execution of the compiled workerd MDX still requires the documented `script-src 'unsafe-eval'` policy and the safe-MDX validation boundary.

The disposable Vercel preview and Neon database imported the same fixture, saved its Visual-mode edit, and retained the rendered page, table, image, and database rows after redeployment. ## Search runtime

Search uses Orama 3.1.18 in process rather than a database-specific full-text engine. Each request reads the current published articles and categories through the shared repository. The search module derives a deterministic signature from that snapshot, reuses the module-local index only while the signature matches, and rebuilds after a publish, unpublish, article edit, category edit, or isolate restart. The database snapshot is authoritative; isolate memory is only a latency optimization.

The index contains title, plain Markdown body text, and category name. Results expose only validated public slugs and a bounded plain-text excerpt. The route normalizes queries, limits them to 200 Unicode code points, disables response caching, and records normalized zero-result queries. Miss sampling has 1,024 conflict-safe slots per UTC day and opportunistically removes records beyond the 30-day cutoff when another miss arrives, bounding anonymous writes and stored row count while keeping a useful MVP sample. Docker/PostgreSQL and Cloudflare/D1 both returned the same typo-tolerant result, while exact canary checks proved miss persistence on both dialects.

## Embedding recovery runtime

Embedding work is post-commit and leased from the database. One recovery invocation reuses a single provider adapter and repository, drains only successfully completed jobs, and stops on idle state, retry scheduling, terminal failure, lease loss, 100 jobs, or a 50-second wall-clock budget. Results and logs expose status, job count, embedded chunk count, activation, and fixed error categories only. Generation IDs, job IDs, provider messages, credentials, and evidence text do not cross that boundary. Missing endpoint, model, or dimension on Postgres and Neon produces a disabled no-op before opening the repository or contacting a provider, so publishing and keyword retrieval stay independent from inference availability.

Cloudflare uses an `AI` binding and the fixed `@cf/baai/bge-base-en-v1.5` contract: 768 dimensions with `cls` pooling. OpenNext's documented [custom Worker pattern](https://opennext.js.org/cloudflare/howtos/custom-worker) preserves the generated fetch handler while adding the scheduled handler, and the Wrangler cron runs every minute in UTC. Cloudflare's current model documentation says [`cls` is more accurate for larger inputs but incompatible with vectors produced by `mean`](https://developers.cloudflare.com/workers-ai/models/bge-base-en-v1.5/), which is why pooling participates in the immutable configuration hash. [Cloudflare Cron Triggers](https://developers.cloudflare.com/workers/configuration/cron-triggers/) can be delivered more than once and can overlap; OPAS relies on generation reconciliation and job leases rather than in-memory process locks.

Docker calls the authenticated internal route from a non-overlapping sidecar every 30 seconds. Vercel invokes the same route with its automatic `CRON_SECRET` bearer header. The maintained Hobby project permits only daily cron execution, so immediate post-response work is the normal Vercel path and the daily cron is missed-work recovery. The route requires a separate secret of at least 32 bytes, compares fixed-size SHA-256 digests, returns `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`, and never reads a request body.

The article row, chunks, incremented workspace index generation, and pending embedding job commit atomically. Drafting or deleting an article removes its evidence and increments the generation in the same operation. Retrieval reads the database generation on every request, caches only one immutable generation per workspace, and revalidates the final bounded candidate identities against the current publication and content hashes before returning them.

## Answer runtime and safety

`POST /api/answers` accepts strict JSON only, limits the complete body to 16,384 bytes, the normalized question to 200 Unicode code points, history to eight messages, 2,048 UTF-8 bytes per message, and 8,192 bytes total, and output to 1,024 tokens. It streams complete NDJSON records with `Cache-Control: no-store`, same-origin resource policy, a deny-all CSP, no buffering, and only bounded public error codes. The browser receives provider name, model, and the operator-authored retention disclosure; it never receives a provider credential. Generation is fully buffered until one exact compact answer or abstention record and the provider finish event pass validation. The source letter is then mapped to the server's retrieved citation; when exactly one retrieved statement contains the normalized answer verbatim, that server-owned match corrects a mismatched model letter. Ambiguous matches stay with the explicitly selected source. Unknown citations, unsafe Markdown, malformed or trailing output, provider error bodies, and stale or no-longer-published evidence cannot cross that boundary.

When no active semantic generation is available, lexical evidence removes fixed English function words and admits a chunk only when it contains at least half of the question's unique remaining terms exactly. The hash-bound synthetic fixture separates all 20 answerable questions from all 10 unsupported questions at that boundary. This precision-first fallback may abstain on a synonym-only question; it prevents high corpus-relative BM25 scores from turning shared words such as “is” or “the” into unrelated evidence.

Orama's hybrid result score is rank-normalized inside each corpus, so the highest unrelated vector hit can otherwise appear to have confidence `1`. OPAS uses Orama hybrid search only to discover candidates, then replaces that relative rank with `max(raw cosine similarity, meaningful exact-term coverage)` before answer admission. The production CROFusion calibration recorded a `0.5877803360` answerable floor, a `0.7538107319` unsupported ceiling, and a `0.0067388597` conflict-canary article gap. Because unsupported and answerable scores overlap and score proximity is not semantic contradiction, the production policy uses a `0.58` sufficiency floor and a zero score-gap conflict band, then requires generation to abstain on unsupported or semantically conflicting evidence. The frozen production run proved 19/20 answerable responses and 20/20 unsupported/adversarial abstentions. A zero-overlap semantic paraphrase can still pass through cosine similarity, while the generated-evidence contract prevents a corpus-relative nearest neighbor from becoming an uncited answer.

Cloudflare generation uses the `AI` binding and is configured for `@cf/meta/llama-3.1-8b-instruct-fp8` through the named `opas-answers` Gateway. The account's auto-created `default` Gateway remains outside the repository's `opas-*` resource boundary and is not an allowed substitute. Every answer request sets `collectLog: false` and `skipCache: true`: the former suppresses the complete AI Gateway log entry and the latter bypasses the AI Gateway response cache. Dashboard inspection after the production acceptance showed 16 requests, 5.76k tokens, 0 errors, 0 cached responses, 16 misses, and 0 hits; Gateway logging and response caching were disabled, and the log view had no rows. The production route returned one D1-grounded cited answer with `Cache-Control: no-store` and reconciled its Workers AI usage and inference lease. This does not claim to disable model-level inference optimizations. Cloudflare's [Workers AI data-use documentation](https://developers.cloudflare.com/workers-ai/platform/data-usage/) says Customer Content is not shared with other customers or used to train models or improve Cloudflare or third-party services without explicit consent, and may be stored when Workers AI is deliberately combined with a Cloudflare storage service. Docker and Vercel use a bounded OpenAI-compatible SSE endpoint, optional bearer credential, `cache: no-store`, no redirects, and unread non-success bodies. Upstream retention on those targets remains the operator's provider decision and must match the browser-visible disclosure.

Workers AI returned adjacent JSON objects during the original protocol, and the strict JSON form measured a 3.709-second direct completion p95 and a 3.909-second retained production first-content p95. Faster model variants completed in about 0.6 seconds but repeatedly emitted malformed records and failed unsupported, adversarial, or conflict cases, so they were rejected. Answer admission has two layers. A one-minute process-local gate accepts at most 120 valid requests; Cloudflare additionally accepts at most 10 per authoritative `CF-Connecting-IP`, represented only by a process-salted in-memory SHA-256 digest. Forwarded addresses are not trusted on Docker or Vercel. This gate is disposable overload shedding. The authoritative cross-instance boundary is an atomic per-workspace database lease that reserves concurrency and the conservative maximum integer-microdollar cost before any provider call.

The lease records the primary provider and model. Cross-provider fallback is disabled unless `OPAS_GENERATION_FALLBACK_ENABLED` is exactly `true` and every second-provider field, retention disclosure, and token price is valid. The providers must differ. The public disclosure names the primary and fallback vendor and model before an answer is returned. Only a retryable timeout, rate limit, or unavailable error before the primary emits any normalized event can start the fallback; authentication, rejected or invalid responses, cancellation, and every failure after output fail closed. Both attempts stay inside the original lease, which reserves the combined maximum cost of both attempts, lasts at least 65 seconds, and reconciles once. Because a failed primary may have consumed unreported tokens, any fallback attempt conservatively charges that full reservation while retaining the fallback vendor and model in the settlement contract.

D1 uses a transactional [`batch()`](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch); Postgres and Neon use a workspace serialization row inside one transaction, including Neon's [non-interactive transaction batch](https://neon.com/docs/serverless/serverless-driver). Both dialects expire stale leases, retain their full possibly spent reservation, enforce rolling 24-hour charged-plus-reserved spend, and insert only when concurrency and budget permit. Completion, cancellation, timeout, invalid output, and provider failure reconcile an active lease once from bounded provider usage. Invalid, absent, over-limit, late, or crash-lost usage charges the reservation instead. Terminal rows older than 31 days are removed opportunistically in batches of at most 100 per new workspace reservation.

## Support handoff runtime

Native and embedded answers expose the same inline contact form after abstention or negative feedback. The client truncates the eight-message transcript to 2,048 UTF-8 bytes per message and 8,192 total and deduplicates citations; the server enforces the same bounds, accepts only the canonical site or configured embed-parent origin, and reconstructs every citation from current evidence. Only then does the portable transaction consume one of 100 rolling daily workspace slots and reserve the UUID before an external call. Contact stays in a separate `support_handoffs` column. Pending duplicates remain unconfirmed and never resend; delivered duplicates are success; failed keys are terminal. Delivery times out at 45 seconds and marks the reservation failed. Node webhooks resolve DNS on every attempt and reject any mixed public/private answer; Cloudflare uses strict-public global fetch.

The guarded Cloudflare bootstrap accepts exactly one handoff mode. `cloudflare-email` requires the structured `SUPPORT_EMAIL` binding, the allowlisted `hello@opas.dev` sender, and an encrypted `OPAS_HANDOFF_TO_EMAIL` fixed destination. `webhook` removes the email binding and sender value and requires an encrypted fixed `OPAS_HANDOFF_WEBHOOK_URL` plus bearer token. The guard rejects mixed modes, plaintext endpoint or token variables, unsafe URLs, and tokens outside 32 through 4,096 UTF-8 bytes. Production now uses the email mode: a cited handoff returned `201 delivered`, its replay returned `200 duplicate`, D1 retained exactly one completed reservation and the reconciled `escalated / support-handoff` outcome, and the addressed message was received in the destination mailbox. All fetch-based delivery uses manual redirect handling: the runtime never follows a redirect, rejects every non-2xx or already-redirected response, cancels the provider body unread, and exposes only fixed errors. ## Feedback and readership signals

The article view beacon and helpfulness form send no cookies and set `credentials: omit`. OPAS does not persist an IP address, user agent, referrer, client ID, or salted requester key. On Cloudflare, where the platform supplies the authoritative `CF-Connecting-IP` header, the server derives a process-salted network key only in memory for a one-minute admission window and limits one requester to 5 feedback attempts and 30 view attempts. Other targets skip requester grouping rather than trusting client-controlled forwarding headers. Every running process still caps feedback and view database attempts at 120 and 600 per minute respectively. These portable counters are best-effort overload shedding, not a deployment-wide abuse firewall; production operators should also apply trusted platform edge limits.

Accepted events occupy one of 1,024 conflict-safe slots per article, event kind, and UTC day. Collisions are intentionally discarded, so the administrator report labels views, feedback, and helpfulness as directional samples rather than unique visitors or exact totals. The report includes only the last 30 days. Old event rows are removed opportunistically when the same article receives another event; an inactive or unpublished article can retain an older free-text comment beyond the reporting window, so this is not a guaranteed 30-day deletion policy.

Feedback accepts only a boolean helpful value and an optional trimmed comment of at most 1,000 Unicode code points. Request bodies are strict JSON, capped at 16 KiB, and never render comments back into public HTML. Draft, missing, and wrong-workspace articles reject both event types.

## Public discovery surfaces

`OPAS_SITE_URL` is the authoritative origin for canonical URLs and absolute machine-readable links. Docker defaults it to `http://localhost:3000`; the maintained Worker pins `https://demo.opas.dev` while its workers.dev endpoint remains a non-canonical fallback. A deployment with another public hostname must set that origin explicitly.

One request-time published-content projection supplies page metadata, `sitemap.xml`, Article and conditional FAQPage JSON-LD, `llms.txt`, `llms-full.txt`, and per-article Markdown. It rejects mismatched workspaces and categories, drafts, and unsafe slugs before any of those surfaces can expose a record. JSON-LD escapes literal `<` before entering a script element. The `.md` path is rewritten to an internal route, returns `text/markdown` without caching, and sends `X-Robots-Tag: noindex, nofollow`; global `Link` and `X-Llms-Txt` headers advertise the two llms documents.
